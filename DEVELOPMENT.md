# Working on this repository

This repository holds one scientific result and the machinery that produces it: a
benchmark of word attribution methods for text classification, measured by
deletion faithfulness. Every reported number is computed from data rather than
typed. Read this file before changing anything.

## Start here, in this order

1. `README.md` states what the library measures and quotes the headline results.
2. `reports/faithfulness_report_2.html` is the generated report of the
   experiment. It is the source of the reported numbers and a useful cross
   check for any change.
3. `benchmarks/README.md` describes the reproducible capsule, a self-contained
   ten second run of the full protocol.

## Layout

| Path | What it holds |
| --- | --- |
| `src/textfaith/` | The library. Attribution methods, the faithfulness measurements, the training pipeline, the checkpoint loader, the word heat map renderer. |
| `benchmarks/` | The reproducible capsule: a self-contained demo of the full protocol with committed results. |
| `notebooks/` | The experiment. Numbered in execution order, see below. |
| `artifacts/` | Checkpoints, cached attributions and tidy results. Not in version control. |
| `data/` | Downloaded corpora. Not in version control. |
| `reports/` | Generated HTML reports and `references.bib`, the single bibliography for the reports. |

## The pipeline

The experiment ran in two rounds. **Round two is the experiment the reported
results come from.** Round one is retained because it reproduces and because its
literature survey fed the reports' related work, but its numbers must never be
mixed with round two's: different sample sizes, a different split protocol and a
different control arm.

| Stage | Round two | Output |
| --- | --- | --- |
| Corpora | `notebooks/08_datasets_v2.ipynb` | `artifacts/{imdb,yelp,agnews}_4000/` checkpoints, 70/15/15 split of 4000 stratified documents |
| Attributions and deletion sweep | `notebooks/09_benchmark_v2.ipynb` | `artifacts/*_v2.parquet` |
| Report | `notebooks/10_report_2.ipynb` | `reports/faithfulness_report_2.html` |

Round one is `notebooks/01_train`, `05_additional_datasets`, `06_benchmark` and
`07_report`, writing the checkpoints `artifacts/sample_2000` (IMDB, named before
the pipeline became multi dataset), `artifacts/agnews_2000` and
`artifacts/yelp_2000`, the parquet files without the `_v2` suffix, and
`reports/faithfulness_report.html`. Notebooks `02` to `04` are development
notebooks that established the measurement, the heat map rendering and the LIME
arm; they cache their own intermediate results but produce no input for either
report.

## Environment and commands

Python 3.13 with `uv`, CPU only PyTorch. Both invocations work and are
equivalent:

```bash
uv run python benchmarks/run_demo.py     # preferred, resolves the project
.venv/bin/python benchmarks/run_demo.py  # the same interpreter directly
```

Notebooks run under the same environment: `uv run jupyter notebook`.

## What is cached, and what regenerating costs

`artifacts/` and `data/` are gitignored, so a fresh clone has neither. Plan
around that before proposing anything that invalidates a cache.

- **Corpora.** `notebooks/01_train` downloads the IMDB export from Kaggle without
  credentials; `notebooks/05_additional_datasets` downloads Yelp polarity and AG
  News from the fast.ai archives. Roughly 700 MB on disk.
- **Attributions.** Recomputing every attribution arm of round two took about
  11 hours of wall clock on an eight core CPU, most of it IMDB and Yelp at the
  500 evaluation budget. The deletion sweep on top of that scores 518,400 cut
  texts.

Cache discipline: every expensive result is written through
`textfaith.experiment.load_or_compute` under a filename that encodes its
parameters, so a differently configured run can never silently reuse an old one.
If you change what a cached function computes, change its filename in the same
commit. Deleting a cache file is the supported way to force recomputation.

## Rules that keep the results honest

These are not style preferences. Breaking them makes the reports claim things
the data does not support.

1. **Never edit `reports/*.html` by hand.** Those files are regenerated by
   notebooks `07` and `10`, whose prose is built from f-strings over the same
   tables. Edit the notebook prose.
2. **Seed 42 everywhere**, for sampling, the classifier head, LIME's dropout
   draws and the gaussian baseline. The study is a single draw and the reports
   say so; do not introduce a second seed silently.
3. **All scores are relative**, expressed as a share of the model's original
   predicted class confidence. Raw probability shifts inherit each classifier
   head's calibration and are not comparable across the three tasks.

## Statistical protocol invariants

A **condition** is one combination of dataset, chunk size, chunk combination and
direction: 3 x 3 x 3 x 2 = 54. Only 42 of those are distinct, because at chunk
size 1 the three combinations coincide by construction. The reports quote both
accountings. Any new comparison must report both.

Within a condition every arm is measured on the same 300 documents, so
comparisons are paired per document. Each condition contributes one Wilcoxon
signed rank test on the per document differences of threshold averaged scores.
Holm correction is applied within each comparison family. Advantages are always
oriented so that a positive number favors the first named source, in both
directions, which means the difference is taken one way for sufficiency, where
lower is better, and the other way for comprehensiveness. `compare_methods()` in
`src/textfaith/experiment.py` implements that orientation for the stored
comparisons; anything new that compares sources should call it rather than
reimplement it.

If you change the grid, the threshold set, the number of explained documents or
the correction procedure, then the condition counts and the report prose move
together. Treat that as one change, not two.

## Result files and their schemas

| File | Shape | Key columns |
| --- | --- | --- |
| `faithfulness_results_v2.parquet` | 518,400 rows, one per document, source, chunk size, combination, direction and threshold | `dataset`, `source`, `method`, `budget`, `is_random`, `chunk_size`, `combination`, `direction`, `percentile`, `observation_index`, `probability_shift`, `original_probability`, `relative_shift` |
| `timing_results_v2.parquet` | 24 rows | indexed by `dataset`, `method`, `budget`; `wall_seconds`, `prediction_count`, `seconds_per_review`, `predictions_per_second` |
| `method_comparison_v2.parquet` | 648 rows, 12 families x 54 conditions | indexed by `comparison`, `dataset`, `chunk_size`, `combination`, `direction`; `average_shift_first`, `average_shift_second`, `first_advantage`, `paired_t`, `wilcoxon_p`, `first_win_share`, `holm_significant` |
| `combination_comparison_v2.parquet` | 12 rows | indexed by `source`, `direction`, `comparison`; `mean_advantage_percent`, `significant_for_first`, `significant_for_second`, `conditions` |

Source names follow `method_budget`, for example `shap_500` or `lime_50`.
Occlusion carries the budget label `word_count` and the random baseline `none`.
Each `artifacts/*_4000/` directory holds `metadata.json` with the accuracies,
the fitted head, the three splits with their embeddings, and the cached
attribution arrays keyed by method and budget.

Attribution caches are payload dictionaries with `attributions`, `wall_seconds`,
`prediction_count` and `parameters`, so timing can never drift from the arrays it
describes.

## Code style

Follow what is already there. The existing modules are the specification.

- Spell identifiers out in full. `predict_probabilities`, not `predict_proba`;
  `MAXIMUM_TOKEN_COUNT`, not `MAX_TOKENS`.
- No em dashes anywhere, in code comments, docstrings or prose.
- YAGNI. No speculative flags, no second comparison method added just in case, no
  third overlapping metric.
- Docstrings explain why a choice was made, not what the code does. See
  `src/textfaith/faithfulness.py` for the register: it explains why the masker
  splits on whitespace, why attributions stay signed, and what each chunk
  combination is for.

## Verifying a change

Before handing work back, run both of these.

```bash
uv run pytest                          # unit tests must pass
uv run python benchmarks/run_demo.py   # the capsule must run end to end
```

If a change affects the measured results, regenerate the report by rerunning
`notebooks/10_report_2.ipynb` and read the changed sections rather than assuming
the prose still matches the tables.

## Open work

In rough order of value:

1. Gradient based attributions, integrated gradients in particular. The encoder is
   differentiable and the protocol would score them unchanged. Their absence is
   currently a stated scope restriction.
2. More explained documents. 300 per dataset is an evaluation time ceiling, not a
   data ceiling, and several conditions sit just outside significance.
3. Multiple seeds. The whole study is one draw, so the condition counts have
   unknown seed to seed variability.
4. Longer texts. The budget and chunking conclusions are stated for medians of 38
   to 157 words, and a 500 evaluation budget sits above all of them, which is
   exactly why SHAP saturates.
5. A control for the residual out of distribution effect that correlates with the
   ranking under test, either remove and retrain or a masker that preserves
   fluency.

## Practical notes

- **Do not run the full pipeline unless necessary.** Recomputing
  attributions costs hours. Almost every question about the results can be
  answered by reading `artifacts/*_v2.parquet` with pandas.
- **If a cache is missing, note it rather than silently recomputing it.** A fresh
  clone has no `artifacts/`, so anything that loads checkpoints or parquet files
  will fail until the notebooks have been run.
- **Prose belongs in notebook markdown cells; numbers belong in the tables.**
  Every number the reports quote is computed from the result files by the
  notebooks, never typed into the prose.
- **The reported results are round two only.** If you find yourself quoting a
  number from `reports/faithfulness_report.html`, stop: that is round one.
- **Report faithfully.** This repository exists to measure whether explanations
  can be trusted. If a check fails or a claim no longer matches the data, say
  that plainly instead of adjusting the claim until it passes.
